根據開發式樣書，當 DI1 (P2.06) 或 DI2 (P2.07) 偵測到高電位（High/1）時，系統將判定為「接點警報」，並依下列步驟處置：

1.  **判定延時**：系統不會立即通報，必須在高電位狀態持續超過設定的「接點判定時間」（1~999 秒）後，才會正式觸發警報。
2.  **雲端通報**：
    *   發送識別碼為 **`AD`** 的 MQTT 電文至 AWS 雲端。
    *   電文內需包含：子機 ID、電文序號、通道編號（1 或 2）及狀態碼（1 代表警報）。
3.  **確認機制 (ACK)**：
    *   發送後啟動計時器等待雲端回應 ACK。
    *   若未收到 ACK 則執行重傳；若超過重傳次數上限，系統會**重置 nRF9151 通訊模組**並重新連線嘗試通報。
4.  **本地與資料保存**：
    *   在除錯終端（Console）顯示「DI1/DI2 Alert」字樣。
    *   若此時發生停電，系統會利用超電容電力將 DI1/DI2 的狀態優先寫入 Flash 記憶體，確保復電後能讀取正確狀態。

**💡 處置重點**：開發時需特別注意「判定時間」的倒數邏輯，若在時間內訊號回到低電位（Normal），則不執行通報動作。
