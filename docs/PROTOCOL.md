# nRF9151 Protocol v1

## 1. 通用電文格式 (Universal Frame Format)
所有通訊均須符合以下結構：

| 欄位        | 長度   | 數值/說明                                    |
| :---------- | :----- | :------------------------------------------- |
| **STX**     | 1 byte | `0x02` (固定值)                              |
| **LEN_L**   | 1 byte | 長度低位字元（從 LEN_L 到 ETX 的總位元組數） |
| **LEN_H**   | 1 byte | 長度高位字元                                 |
| **OP_CODE** | 1 byte | 功能識別碼（定義見下表）                     |
| **Payload** | 可變   | 實際數據內容                                 |
| **ETX**     | 1 byte | `0x03` (固定值)                              |
| **CRC_1**   | 1 byte | 校驗碼 1 (從 LEN_L 計算至 ETX)               |
| **CRC_2**   | 1 byte | 校驗碼 2                                     |

---

## 2. 指令定義與 Payload 格式

### A. nRF54L15 -> nRF9151 (主動傳送)

| 功能項目                    | OP_CODE | Payload 格式範例                                                                                        |
| :-------------------------- | :------ | :------------------------------------------------------------------------------------------------------ |
| **1. 系統日誌 (Log)**       | `0xC0`  | 以 ASCII 字串傳送。範例：`[MCU][00:00:01.002,281] <inf> main: Hello World!`                             |
| **2. MQTT 發布內容**        | `0xC1`  | 包含 Topic 與內容。格式：`[Topic長度(1B)][Topic字串][MQTT內容(JSON)]`。範例：`[MQTT]{"v":3.3,"t":25.0}` |
| **3. 推送設定值 (Boot-up)** | `0xC2`  | 傳送存在 Flash 的設定 JSON。範例：`[SETTINGS]{"key1": "string", "key2": 123}`                           |

### B. nRF9151 -> nRF54L15 (管理與回饋)

| 功能項目              | OP_CODE | 說明                                                                       |
| :-------------------- | :------ | :------------------------------------------------------------------------- |
| **1. 要求讀取設定值** | `0xD0`  | 當 nRF9151 重啟或需要同步時發送，觸發 nRF54L15 回應 `0xC2`。               |
| **2. 網路狀態通知**   | `0xD1`  | 由 nRF9151 通知目前 LTE 或 DECT NR+ 的連線狀態（如：`0=離線, 1=已連線`）。 |
| **3. RTC 時間同步**   | `0xD2`  | nRF9151 從 LTE 網路取得正確時間後，傳送給 nRF54L15 更新時鐘。              |

---

## 3. 通訊範例分析 (以 Log 為例)
若 nRF54L15 要送出一條 Log：`[MCU] Hello`

1.  **STX**: `0x02`
2.  **LEN**: 假設 Payload 為 11 bytes + OP(1) + ETX(1) = 13 bytes (`0x0D, 0x00`)
3.  **OP_CODE**: `0xC0`
4.  **Payload**: `5B 4D 43 55 5D 20 48 65 6C 6C 6F` (ASCII: [MCU] Hello)
5.  **ETX**: `0x03`
6.  **CRC**: 計算後的 2 bytes

## 4. 未來需要的新增指令 (規格書有提到，但暫不實作)
基於 TJ3 系統的特性，建議增加以下指令以優化通訊：
*   **Modem 控制指令 (`0xE0`)**：nRF54L15 可要求 nRF9151 執行硬體重置（Reset LTE）或進入低功耗模式。
*   **OTA 狀態更新 (`0xF0`)**：當 nRF9151 正在進行 4G 韌體下載時，同步通知 nRF54L15 以便顯示對應的 LED 狀態。
