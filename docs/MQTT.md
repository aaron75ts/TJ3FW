

# MQTT 通訊識別代碼 (Identification Code)
在 MQTT 通訊中，這些代碼用於 Topic 路徑末端及 Payload 內容中，作為區分不同功能的依據。

## 1. 警報與定期通報（由本機主動發送）
| 識別碼 (ASCII) | 功能名稱          | 說明                                             | 來源 |
| :------------- | :---------------- | :----------------------------------------------- | :--- |
| **AD**         | 接點警報/復歸     | 當 DI 輸入狀態變更並經過判定時間時發送。         |      |
| **EB**         | 輕漏電警報/復歸   | 漏電電流超過「輕漏電」判定閾值時發送。           |      |
| **EC**         | 重漏電警報/復歸   | 漏電電流超過「重漏電」判定閾值時發送。           |      |
| **BH**         | 新微地絡警報      | 地絡電流 Ig 超過設定閾值且達到超過時間時發送。   |      |
| **BI**         | 間歇地絡警報      | 地絡電流異常但非持續性，符合間歇判定條件時發送。 |      |
| **AB**         | 停電通報          | 系統偵測到電壓過低並由備援電池供電時發送。       |      |
| **AC**         | 復電通報          | 系統恢復供電並重新連網後發送。                   |      |
| **AE**         | 死活監視/測試通報 | 依設定間隔發送，包含子機連線狀態與連線台數資訊。 |      |
| **FE**         | 過負荷警報/復歸   | 負荷電流（CT 測量值）超過設定上限時發送。        |      |
| **FA**         | 測量值定期通報    | 定期發送 6 通道電流值、地絡電流與 DI 狀態。      |      |
| **GB**         | 需量注意警報      | 預測電力或目前電力達到「注意」界限時發送。       |      |
| **GC**         | 需量限界警報      | 電力達到「限界」界限時發送。                     |      |
| **GA**         | 需量定期通報      | 每 30 分鐘發送一次該時段的累計電力量 (kWh)。     |      |

## 2. 雲端輪詢要求 (Polling Requests)
由 AWS 雲端發送至本機（親機/子機），要求回報資訊或變更設定。

| 識別碼 (ASCII) | 功能名稱             | 說明                                               | 來源 |
| :------------- | :------------------- | :------------------------------------------------- | :--- |
| **PA**         | 需量現在值要求       | 遠端讀取目前電力、預測電力與警報狀態。             |      |
| **PB/PC**      | 需量設定要求/變更    | 讀取或修改需量目標值、脈衝係數與未判定時限。       |      |
| **PF**         | 需量通報啟動/停止    | 開啟或暫停 30 分鐘一度的需量定期通報。             |      |
| **PG**         | 連線資訊要求         | 取得 DECT NR+ 網路 ID、頻道、RSSI 與子機詳細狀態。 |      |
| **PH**         | 漏電即時資訊要求     | 遠端讀取 6 個 CT 的即時漏電電流值與接點狀態。      |      |
| **PI/PJ**      | 輕漏電設定要求/變更  | 讀取或遠端修改 6 通道的輕漏電警報電流閾值。        |      |
| **PK/PL**      | 重漏電設定要求/變更  | 讀取或遠端修改 6 通道的重漏電警報電流閾值。        |      |
| **PN**         | 歷史需量要求         | 指定特定日期時間，回溯讀取 30 分鐘電力量。         |      |
| **PO/PP**      | 時間確認/變更        | 遠端校正或讀取本機內部的 RTC 時間。                |      |
| **PQ**         | 軟體版本確認         | 取得本機韌體 (Software Version) 資訊。             |      |
| **PU/PV**      | AI 設定要求/變更     | 修改漏電檢測方式 (Io/Ior)、變壓器種類與相位補正。  |      |
| **PW**         | 相位/Io 資訊取得     | 遠端讀取各通道的 Io 值、Ior 值及相對相位角。       |      |
| **QL/QM**      | 4G LTE 設定要求/變更 | 遠端設定通報伺服器的 IP 地址、Port 與監視間隔。    |      |

**💡 註記**：BLE 的 OP_CODE 使用 **16 進制 (Hex)** 定義，而 MQTT 的識別碼則是使用 **2 位元 ASCII 字元** 作為指令標籤。


## 範例

根據開發式樣書（來源），以下為一個完整的 MQTT **「需量現在值要求 (PA)」** 的 Request 與 Response 範例。

在此範例中，假設：
*   **親機 (Gateway) MainID**：`GW0001`
*   **子機 (Peripheral) PeriID**：`PE0002`
*   **識別代碼 (ID Code)**：`PA` (需量現在值要求)

---

### 1. 雲端發送要求 (Polling Request)
當 AWS 雲端欲主動向本機索取測量數據時，會發送此電文。

*   **Topic (主題)**：`kyosvr/GW0001/PE0002/cmd`
*   **Payload (電文內容)**：
    `\x02PE0002PA0102GW0001\x03`

**欄位解析：**
| 欄位名稱         | 內容範例 | 說明                                               | 來源 |
| :--------------- | :------- | :------------------------------------------------- | :--- |
| **STX**          | `\x02`   | 電文啟始符號                                       |      |
| **子機端末名稱** | `PE0002` | 設定的 Peripheral 名稱（固定 6 bytes，不足補空格） |      |
| **識別 Code**    | `PA`     | **Demand 現在值要求**                              |      |
| **電文番號**     | `01`     | 雲端管理用的序號（'00'~'99'）                      |      |
| **端末番號**     | `02`     | 子機編號（'00'為本體，'01'~'99'為子機）            |      |
| **親機 MainID**  | `GW0001` | 親機（Central）的終端名稱                          |      |
| **ETX**          | `\x03`   | 電文結束符號                                       |      |

---

### 2. 設備回傳數據 (Device Response)
本機收到 Polling 要求後，會將目前的需量數據打包並回傳。

*   **Topic (主題)**：`kyokuto/GW0001/PE0002/PA`
*   **Payload (電文內容)**：
    `\x02PE0002PA0102GW00011230050006501000080000048000\x03`

**回傳電文詳細數據解析 (Data Content)：**
根據來源，回傳數據接在 MainID 之後：
1.  **時刻 (hhmm)**：`1230`（表示 12 點 30 分）
2.  **現在電力**：`0500`（500 kW）
3.  **預測電力**：`0650`（預測 30 分鐘後為 650 kW）
4.  **限界電力**：`1000`（警報界限 2 設定值）
5.  **注意電力**：`0800`（警報界限 1 設定值）
6.  **警報狀態 (e/f)**：`00`（0:通常，1:警報中；目前皆為正常）
7.  **前回需量**：`0480`（30 分鐘前的累積電力值）
8.  **LED/Pulse 狀態**：`00`（其他週邊異常狀態）

---

### 關鍵規則總結
*   **Topic 命名**：發送到本機的主題路徑前綴固定為 `kyosvr/`，本機回傳的主題路徑前綴固定為 `kyokuto/`。
*   **ID 識別**：所有電文必須同時包含 **MainID** (親機) 與 **PeriID** (子機) 的名稱，以便雲端 Broker 識別數據來源。
*   **控制符號**：所有電文必須以 `\x02` (STX) 開頭，並以 `\x03` (ETX) 結尾。
