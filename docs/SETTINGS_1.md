根據開發式樣書與相關技術文件（以下簡稱「這些來源」），TJ3-nRF 系統對於設定值的儲存與存取有嚴格的硬體規範與軟體校驗要求，主要歸納如下：

### 1. 儲存媒介與分工
設定值根據其性質儲存於不同的硬體組件中：
*   **長期儲存 (External Flash)**：MCU 模組配置了一顆 **64Mbit 的外部 SPI NOR Flash**，用於持久化儲存系統參數、1 分鐘值（保存 90 天）及 30 分鐘值（保存 1 年）的歷史數據。
*   **計量晶片暫存器 (ATM90E26 Registers)**：計量相關的校正參數儲存在 ATM90E26 的內部暫存器中。由於暫存器在重置後會恢復預設值，因此 **MCU 必須在啟動或偵測到錯誤後，從 Flash 讀取設定並重新載入 (Reload) 至晶片中**。
*   **啟動檢查**：系統啟動時會執行「啟動時自己診斷」，包含檢查序列 **EEPROM 的讀取狀態**與**參數的整合性 (Consistency Check)**，若發現異常會透過 LED 顯示錯誤。

### 2. 設定值存取途徑
系統提供三種主要管道進行設定值的讀取與變更：
*   **藍牙 (BLE) 存取**：
    *   手機 APP 透過 **UUID `...8c02...` (Meter Config)** 的特徵值進行 **READ** 與 **WRITE** 操作。
    *   使用特定 OP_CODE 進行變更，例如 `0xB5` 用於 AI 設定變更，`0xA5` 用於 MQTT 設定變更。
    *   **硬體保護**：必須長按本機的 **"S" (Set Mode) 按鈕 3 秒以上**，才能解鎖並允許從藍牙 APP 修改設定。
*   **雲端 (MQTT) 遠端存取**：
    *   雲端發送 **Polling 指令**（如 `PC` 指令變更需量設定、`PJ`/`PL` 變更漏電閥值）來遠端修改參數。
    *   設備在成功變更後會回傳 Result Code '0'，並通常會執行 **Reset 處理**以讓新參數生效。
*   **內部讀取確認**：為確保 SPI/UART 通訊可靠性，讀取關鍵暫存器後建議讀取 **`LastData` (06H)** 暫存器進行比對，確認讀數正確無誤。

### 3. 設定值的整合性與整合保護 (Integrity)
為了防止錯誤的設定導致計量功能異常，系統設有校驗機制：
*   **暫存器校驗和 (Checksum)**：
    *   計量配置參數由 **CS1 (2CH)** 保護；量測校正參數由 **CS2 (3BH)** 保護。
    *   當 `CalStart` (20H) 設定為 `8765H` 時，晶片會自動診斷設定值與 Checksum 是否匹配，若不符則會停用計量功能並觸發 **WarnOut** 訊號。
*   **寫入順序要求**：部分參數有特定的先後順序，例如 `PLconstH` (21H) 必須在 `PLconstL` (22H) 配置完成後才會正式生效。

### 4. 停電時的特殊處理
當系統偵測到停電 (Power-off detect) 時，會利用備用電力（超電容）執行最後的數據存取動作：
*   **狀態保存**：系統會強制將目前的**接點 ON/OFF 狀態**、**電文序號**、**漏電/負荷電流測量值**及**需量脈衝積算值**寫入 Flash 儲存。
*   **復電讀取**：復電後系統會優先讀取停電前保存的數據，確保需量演算與監控能接續進行。

**💡 總結**：設定值存取的核心原則是 **「Flash 長期保存、啟動診斷完整性、變更需硬體授權（按鈕）、寫入必經校驗（Checksum）」**，以確保裝置在複雜的電網環境下維持計量精確與設定安全。
