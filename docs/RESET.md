根據開發式樣書與硬體說明文件，TJ3-nRF 系統在不同故障情境下會採取不同的重置策略。以下為您整理 **nRF9151 (通訊模組)** 與 **Power Reset (系統電源重置)** 的觸發時機：

### 一、 何時需要重置 nRF9151 (通訊模組)
nRF9151 在系統中擔任 DECT NR+ 與 LTE 4G 通訊的角色。重置此模組主要是為了**恢復因網路異常或伺服器無回應導致的通訊中斷**：

1.  **雲端通報 ACK 逾時且超過重傳次數**：
    *   當本機發送**接點警報 (AD)**、**漏電警報 (EB/EC)**、**地絡警報 (BH/BI)** 或**過負荷警報 (FE)** 後，會啟動計時器等待 AWS 雲端的 ACK 回應。
    *   若在規定的重傳次數內皆未收到 ACK，系統會執行的恢復流程為：**切斷回線 → 重置 nRF9151 模組 (4G/KDDI 模組) → 重新連線 → 再次嘗試通報**。
2.  **定期通報異常**：
    *   在執行**測量值定期通報 (FA)** 或**測試定期通報**時，若同樣遇到重傳次數超過上限且無法復歸的情況，也會啟動模組重置以進行回復處理。

### 二、 何時需要執行 Power Reset (系統/電源重置)
Power Reset 通常涉及整機或關鍵計量組件的重新啟動，用於**參數生效或處理嚴重的硬體錯誤**：

1.  **遠端設定變更完成後**：
    *   當雲端透過 **PC 指令 (Polling 設定變更要求)** 遠端修改了「脈衝係數」、「警報閥值」或「未判定時限」等核心參數時，裝置在回傳設定成功的 Response 後，會自動執行 **Reset 處理** 以確保新設定被正確加載並生效。
2.  **計量晶片 (ATM90E26) 發生嚴重錯誤**：
    *   當計量晶片的 `WarnOut` 腳位變為 High，代表發生**計量參數校驗錯誤 (Checksum Error)**。此時 MCU 必須重置 ATM90E26 並重新加載校正參數。
    *   若發生計量錯誤且無法透過軟體指令校正時，MCU 可透過 GPIO 控制系統電源進行 Reset。
3.  **系統初始化或復電**：
    *   在電源投入瞬間，系統會自動觸發 **Power-on Reset**。
    *   若系統偵測到電網電壓過低進入停電模式，復電後也會重新執行初始化流程。

### 三、 總結對照表

| 重置對象               | 觸發原因                     | 主要目的                               |
| :--------------------- | :--------------------------- | :------------------------------------- |
| **nRF9151 (Modem)**    | 通報警報後多次未收到雲端 ACK | 強制重新撥號連網，恢復 MQTT 通訊路徑   |
| **Power Reset (系統)** | 收到 `PC` 指令完成設定變更後 | 確保新的硬體參數與運算常數生效         |
| **Power Reset (系統)** | 計量參數發生 Checksum 錯誤   | 修正 ATM90E26 的運行狀態，防止數據誤報 |
