根據開發式樣書（來源），MQTT **PW** 識別碼用於 **「Polling 位相・Io 漏電電流值要求」**。此功能允許雲端（AWS）遠端取得各通道的原始漏電電流（Io）、相對相位角（Phase Angle）以及計算後的抵抗分漏電電流（Ior）。

以下為完整的 MQTT 要求與回應範例：

### 1. 雲端發送要求 (Polling Request)
當雲端欲索取詳細的相位與 Io 資訊時發送此電文。

*   **Topic (主題)**：`kyosvr/GW0001/PE0002/cmd`
*   **Payload (電文內容)**：
    `\x02PE0002PW0802GW0001\x03`

**欄位解析：**
| 欄位名稱           | 內容範例 | 說明                     | 來源 |
| :----------------- | :------- | :----------------------- | :--- |
| **STX**            | `\x02`   | 電文啟始符號             |      |
| **子機端末名稱**   | `PE0002` | 6 bytes ASCII，子機名稱  |      |
| **識別 Code**      | **`PW`** | **位相・Io 要求**        |      |
| **電文序號 (Seq)** | `08`     | 雲端管理序號 ('00'~'99') |      |
| **端末番號 (Num)** | `02`     | 子機編號 ('00'~'99')     |      |
| **親機 MainID**    | `GW0001` | 6 bytes ASCII，親機名稱  |      |
| **ETX**            | `\x03`   | 電文結束符號             |      |

---

### 2. 設備回傳數據 (Device Response)
本機收到要求後，會打包 6 個通道的所有量測參數並回傳。

*   **Topic (主題)**：`kyokuto/GW0001/PE0002/PW`
*   **Payload (電文內容)**：
    `\x02PE0002PW990802GW00010150+090000000200-120001000000+00000000...[其餘通道]...\x03`

**詳細數據欄位解析 (以 CT1 與 CT2 為例)：**
根據來源，回應電文在 MainID 之後緊接著各通道數據：

1.  **固定填充碼**：`99` (根據來源格式定義)。
2.  **序號與編號**：`0802` (對應 Request 的序號與端末號)。
3.  **CT1 數據**：
    *   **IoValue**：`0150` (代表 Io = 150 mA)。
    *   **PhaseAngle**：`+0900` (5 位 ASCII，代表 +90.0°)。
    *   **IorValue**：`0000` (代表 Ior = 0 mA)。
4.  **CT2 數據**：
    *   **IoValue**：`0200` (代表 Io = 200 mA)。
    *   **PhaseAngle**：`-1200` (5 位 ASCII，代表 -120.0°)。
    *   **IorValue**：`0100` (代表 Ior = 100 mA)。
5.  **CT3 ~ CT6**：依此類推，每個通道佔用 13 bytes (4+5+4)。

---

### 關鍵規格總結
*   **相位角格式**：使用 5 位 ASCII 字元，範圍從 **`-1800` 到 `+1800`**，代表實體角度的 -180.0° 到 +180.0°。
*   **電流格式**：Io 與 Ior 均為 4 位 ASCII 字元，範圍為 `0000` 到 `9999` (單位為 mA，最大量測至 2000mA)。
*   **Topic 規則**：回傳主題路徑會將原本 Request 的 `cmd` 替換為指令代碼 **`PW`**，且前綴改為 `kyokuto/`。
