根據開發式樣書，App 設定判定時間與停電時的數據保存機制如下：

### 一、 如何透過 GATT 設定判定時間
App 需透過 **Energy Service** 的 **Command 特徵值** 來變更 DI 判定時間：
1.  **實體解鎖**：使用者必須先長按設備本體的 **"S" (Set Mode) 按鈕 3 秒以上**，藍牙端才能獲取寫入權限。
2.  **存取特徵值**：App 對 UUID `4d6f8c03-4b9a-4c1b-9a61-112233445500` (Command) 發起 **WRITE** 操作。
3.  **使用 OP Code 0xB5**：發送「AI 設定變更」指令，封包內包含以下欄位：
    *   **DI_1/2_ON_TIME**：接點警報判定時間（2-byte HEX，單位為秒）。
    *   **DI_1/2_OFF_TIME**：接點復歸判定時間（2-byte HEX，單位為秒）。
4.  **確認機制**：設備收到後會透過 **INDICATE** 將原封包 Echo 回傳，作為 ACK 確認。

### 二、 停電時寫入 Flash 的關鍵數據
當 P1.03 偵測到電力中斷，系統會利用超電容電力將下列項目優先保存至 Flash 記憶體，確保復電後能接續任務：
1.  **接點狀態**：DI1 與 DI2 目前的 ON/OFF 狀態。
2.  **計量數值**：最新的漏電 (Io/Ior)、地絡 (Ig) 與負荷電流的測量數據。
3.  **需量統計**：目前累積的所有 Demand 值以及 Pulse 脈衝積算回數。
4.  **通訊資訊**：目前的電文序號 (Sequence Number)，確保復電後發送 AC 電文時序號不中斷。
5.  **系統診斷**：目前的所有錯誤狀態碼 (Error Status) 以及停電發生的精確時間。

**💡 核心觀念**：App 設定就像是更改「警報準則」；而 Flash 保存則像是飛機失事前自動紀錄的「黑盒子」，保存 DI 狀態與需量數據是為了讓系統復電後能精準銜接 30 分鐘的需量時限演算。
